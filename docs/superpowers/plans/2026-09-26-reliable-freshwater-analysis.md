# 淡水调查可信分析与复现实施计划

> 执行状态（2026-09-26）：A–C、E 的主要实现已落地，GUI 积分与 replay 共用预处理流程；GUI 积分成功结果现按通道关联独立运行清单（配置、输入 SHA-256、软件及实现摘要、线/区域/mask 摘要），并随 `.ep` 保存。用户目录中连续 10 个 RAW（约 1.05 GB）已完成导入、接缝、积分、保存重开与 replay 一致性验收；现场异常组合和多通道内存观察仍待执行。乱序、重叠、重复 ping、ping 间隙和 GPS 覆盖范围的自动化回归已覆盖。默认测试 308 通过、真实数据测试 346 通过。ESP3/Echoview 基准和 30 GB 第二阶段未验收。未经用户明确要求，不执行 commit、push 或发布。

**Goal：** 先用约 1 GB 的现场多文件数据，完成选定通道的可靠积分与密度分析，保证界面、保存、重开、重算和导出一致。

**Architecture：** 保留 PySide6、echopype 和现有计算模块。全通道原始数据单份持有；活动通道使用共享原始数组的视图，修正数据单独持有。GUI 与项目重算共用计算步骤，按通道保存参数、标注及结果状态。

**Tech Stack：** Python、PySide6、echopype、xarray、NumPy、pandas、h5py；本阶段不增加前端框架或通用任务调度框架。

## 1. 已确认的产品选择

| 决策 | 已确认内容 |
|---|---|
| 主要使用者 | 用户本人，完成淡水调查 |
| 第一优先级 | 积分与密度的可靠性、可复现性 |
| 参数修改 | 标记相关结果过期；用户明确运行后计算 |
| 通道 | 选定通道统一用于声图和单通道分析 |
| 标注 | 各通道独立保存底线、人工噪声、区域和结果 |
| 过期结果 | 可以查看和随项目保存；禁止作为正式分析结果导出 |
| 验收材料 | 多份现场 RAW，没有参考软件数值结果 |
| 本轮规模 | 约 1 GB；具体文件由用户在实施验收时指定 |
| 后续规模 | 超过 30 个文件、超过 30 GB，单独第二阶段开发与验收 |

本轮保留鱼群与 SED，修复其旧结果残留和通道误用，但不扩展其科学算法。结果可复现不等于已证明与 Echoview/ESP3 等价。CLI 保持移除。

## 2. 必须修复的已核实问题

1. “应用全部参数”以不完整的 UI 字典替换 `_config`，会丢失调查信息、输出路径和未展示的设备参数。
2. 参数/区域变化没有完整触发失效标记；多个导出入口绕过失效检查，可能交付旧结果。
3. `.ep` 使用默认 DataFrame JSON：小量 ABC 可能变成零，纳秒时间变成毫秒整数，数值及类型不能可靠往返。
4. “保存的去噪策略”与“内存数据是否已经去噪”共用 `_noise_applied` 语义，已去噪项目仅打开再保存就可能改变下一次重算。
5. SED 返回空结果时只清除声图点，旧表、导出缓存和保存数据可能残留。
6. Sv CSV 从单一 DataArray 导出，会遗漏存放在 Dataset data variables 中的实际深度、距离或 GPS。
7. 通道下拉缺少完整选择链路，多处固定取首通道；只有频率文本不足以唯一识别同频通道。

以上问题是本轮实施依据；不以覆盖率数字或测试通过总数替代验收。

- [ ] 参数信号只更新设置并标记过期，不启动 Worker；色标、缩放等显示设置不使科学结果过期。
- [ ] 复用 `_stale_results` 管理当前通道状态。积分阈值、EDSU、层宽、TS 假设改变使积分/密度过期；去噪或人工 mask 改变使修正数据和依赖结果过期；线与区域变化使相关结果及依赖该区域估噪的修正数据过期。鱼群参数不应使没有依赖鱼群的积分失效。

- [ ] 成功完成才替换相应结果并清除过期状态；失败保留旧结果及过期标记。空结果也是本次有效结果，必须清空旧表、缓存和覆盖层；部分文件失败保持“不完整”状态。

### 任务 B：接通通道身份与独立状态

主要位置：现有 `FileMixin` 的捕获/恢复逻辑、`property_panel.py`、`workers.py`、`src/core/sed.py`。

- [ ] 以原始 `channel` 字符串为唯一 ID，频率只用于显示。下拉条目保存 ID，同时显示频率和必要的通道名称，允许区分同频通道。
- [ ] `merged.ds` 持有全通道原始数据；活动 `_ds_Sv` 是保留 channel 维度的单通道视图。创建新项目/重新校准才替换原始数据；去噪、mask 或切换通道不得将活动视图覆盖回全通道数据。
- [ ] 复用当前 handler 的状态捕获/恢复方式，以 `channel_states[channel_id]` 保存通道处理参数、线及撤销状态、区域开关、mask、结果、实际运行参数和过期标记。切换前捕获，切换后恢复；未分析通道从默认状态开始，不复制另一通道标注。
- [ ] 运行时每通道最多保留一份对应的 `Sv_corrected` 和计算状态，原始数据始终引用全通道源数据；这些大数组不写入 `.ep`。若运行缓存已释放，切回时明确标记修正数据待生成，不把原始数据冒充已去噪数据。
- [ ] 项目级 RAW、输出目录、调查信息和设备/校准设置只保存一份；通道状态只保存可独立调整的分析设置。保存项目时先捕获活动通道，避免快照落后于界面。
- [ ] 当前通道的 Sv、深度、距离、校准参数用于所有单通道 Worker。SED 还须按同一 ID 选择 TS、Beam_group 复采样和角度参数；缺少该通道明确报错，不退回其他通道。
- [ ] 多频入口显式使用全通道原始 Sv，并标明未应用各通道去噪及人工标注；本轮比较范围固定为各通道完整有效采样范围。处理后多频比较不列入本轮。
- [ ] 修正数组写入前取得独立所有权；跨通道不得共享可写 `Sv_corrected`。切换只共享原始数据，不 deep-copy 全通道 Dataset。

验证：双通道构造数据使用不同 Sv 值、深度和同频名称；选 B 时显示、积分和 SED 输入都属于 B；A/B 各有不同底线和 mask，反复切换及保存重开后互不污染；任一处理后原始 Sv 逐点不变。原始数组共享通过内存共享断言验证。

### 任务 C：可靠保存项目与结果表

主要位置：`src/core/ep_project.py`、`src/gui/handlers/file_handlers.py`；表格读写集中在一个专用模块 `src/core/project_tables.py`，避免四类结果各写一套转换。

- [ ] `.ep` 格式升级至 1.3，新增选定通道 ID 和按通道保存的状态。HDF5 通道组用稳定编号，原始 ID 存为 UTF-8 属性，避免 ID 中的斜杠被解释成路径。
- [ ] 新结果表按列保存 HDF5 原生数值类型；时间按原单位的整数值及 datetime 类型标记保存；字符串采用 UTF-8。保存列顺序、行数、索引及缺失值信息，区分“未计算 None”和“已计算空表”。仅支持项目实际结果使用的数值、布尔、时间和字符串类型；遇到不支持的对象列应明确失败，不能静默 stringify。
- [ ] 继续支持读取 1.0–1.2 的旧 JSON 表；不能恢复此前已损失的精度。旧结果作为待核验历史结果，重算前不得正式导出。
- [ ] 旧项目无通道 ID：先保留为“旧首通道绑定”；在相同 RAW 重新加载后绑定实际首通道并记录“推断迁移”，不向其他通道复制标注。缺少对应数据或校验失败时拒绝绑定。
- [ ] 保留现有临时文件+原子替换保存方式；迁移只在明确保存时写入，读取旧项目不改写原文件。

### 任务 D：让 GUI 与重算使用同一处理策略

主要位置：`src/core/processing.py`、`src/core/replay.py`、现有积分 Worker 和项目打开流程。

- [ ] 将每通道的持久化去噪策略 `noise_enabled` 与运行状态 `_noise_applied` 分开。前者仅因用户明确启用/关闭自动去噪而改变；后者描述当前内存数据，重开后可以为 False。
- [ ] 旧 `processing_state.noise_applied` 只在迁移时用于初始化策略。缺少策略的旧项目提示确认设置，不能静默推断为“未去噪”。
- [ ] 重开仅校准并恢复历史状态，不自动开始耗时分析；显示“修正数据待生成”。已有去噪策略继续保留，打开→保存不改变它。提供明确的“关闭自动去噪”设置，清除算法修正但保留人工 mask。
- [ ] 在 `processing.py` 集中一条固定流程，由 GUI 明确的“按当前设置重算积分”和 replay 共同调用：选择通道→按已保存区域进行可选背景去噪→人工 mask→区域裁剪→建立网格并积分。底线作为已保存输入，不在积分重算中重新检测；本轮不建立历史操作回放系统。
- [ ] 修改区域后，原来按旧区域生成的修正数据失效；明确重算执行上述完整流程。单步处理按钮仍保留，不能让它们把旧处理结果误标为符合新设置。
- [x] 每次成功结果记录实际通道、有效参数、线/区域/mask 摘要、输入文件校验和、实际软件版本及计算实现摘要。保存设置变化不能改写旧结果的运行记录。
- [ ] replay 默认处理已保存的活动通道，并在输出说明中明确通道及处理策略；输出新目录，不覆盖项目和既有结果。原有 `replay_project(project_path, output_dir, progress=None)` 接口保持。

验证：A 去噪并保存→打开 A 不处理→保存 B，A/B 的有效策略一致；同版本下两者重算逐格计数一致，浮点结果 `rtol=1e-12, atol=0, equal_nan=True`；GUI 与 replay 同设置结果相同。元数据时间等运行记录允许不同。用户明确关闭去噪才改变对应结果与策略。

## 4. 第二阶段：30 GB 以上调查

本节是下一阶段目标及启动条件，不与第一阶段混成一次大改。待第一阶段通过、取得代表性大调查样本后，基于实测再写独立实施计划。

## 5. 实施组织与完成标准

执行次序：A→B→C→D→E→F；C 的独立表格序列化和 E 的 CSV 字段修复可在 A 期间先行实现与验证，最终集成顺序保持不变。共享 handler 的通道和状态改动由同一负责人统合，避免并行相互覆盖。

第一阶段完成标准：当前通道数据、标注和结果一致；保存往返精度与类型不变；打开再保存不改变处理策略；同输入、同设置、同版本的 GUI/重算一致；过期或不完整结果不能正式导出；约 1 GB 现场流程验收完成。科学外部对照与 30 GB 支持继续单独列为未验收。
