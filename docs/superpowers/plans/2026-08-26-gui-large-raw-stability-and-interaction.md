# GUI 大规模 RAW 稳定性与 Echogram 交互实施方案

> 本方案在 2026-08-26 经用户确认后执行；不自动 commit 或 push。

## 目标

解决大量 `.raw` 导入时的内存放大、主线程阻塞和错误不可追踪问题；保证 8 个以上文件整体底线检测有明确结果；让每个功能参数独立自动应用；新增手爪模式左键拖动 Echogram。

## 已确定行为

- 多文件导入：单个文件失败时继续处理成功文件，并在消息面板报告失败文件、阶段和 traceback；全部失败或最终合并失败则终止。
- 底线检测：超过 7 个文件仍采用合并后整体检测；检测结果全为 `NaN` 时必须显示明确诊断。
- 参数应用：每个功能参数独立自动应用，带防抖和旧任务结果丢弃；噪声变化只更新噪声结果，并把底线、鱼群、积分标记为过期，不自动级联。
- 鼠标交互：新增手爪模式，左键拖动平移；保留中键拖动兼容操作。
- 错误显示：不使用阻塞式 `QMessageBox.critical()` 锁住主窗口；完整错误进入可滚动、可复制的消息面板。

## 实施顺序

1. 先写并运行导入容错、日志、长底线和手爪交互的失败测试。
2. 修改 `MergeFilesWorker` 和文件处理器，移除无用 `EchoData` 列表和主线程完整 Sv 增量 `vstack`，加入失败文件报告。
3. 修改主窗口消息面板和 Worker 错误处理，保证日志可滚动且错误后主窗口仍可操作。
4. 为底线检测增加尺寸/有效点诊断，并对超长底线做显示级抽样，保留完整底线数组用于分析。
5. 为噪声、底线、鱼群、积分和 SED 参数增加独立信号与防抖任务；用任务版本号阻止旧结果覆盖新结果。
6. 在工具栏和 OpenGL Renderer 中新增 `PAN` 模式，左键拖动更新视口偏移。
